# LiveBand

An offline Windows app that listens to a live singer and plays drums,
percussion, bass and keys that follow the singer's key and tempo. Built for the
Nigerian market: Afrobeats and worship styles first.

**Status: Phase 4 built** (feel, control and the 6/8 style; laptop checks pending). Sing
a phrase or two and the app finds your key, allowing for singing sharp or flat; tap the
beat four times and the band comes in on the fifth, in your key: an **Afrobeats** band, or
a **Nigerian worship** band in 6/8 led by the piano and pad. The band follows how loud you
sing, playing harder when you sing out and switching to a fuller version after two loud
bars. Re-tap to pull it onto your beat within a bar, nudge the tempo 1% with the arrow
keys, and bring the next parts in early. From Phase 3: the key detection, bass, piano and
pad, and the staged entry. From Phase 2: count-in, verse and chorus with fills, a final
hit, MIDI pedals. From Phase 1: the live note display and pitch graph, voice files and
test recordings.

![LiveBand playing the worship style in 6/8 in G major](docs/images/phase4/app-worship.png)

On real singing it was not tuned on (94 recorded children's songs), the key locks after a
median 6 s of voice and is exact 94% of the time, and exact, relative or a fifth away
98%; after only 3 s the best guess is exact 80% of the time. In the engine tests the
drums come in 0.3 ms from the tapped beat, and re-tapping puts the band on the new beat
within one bar; on 40 clips of real singing, 97% of pitch frames are within 50 cents of the
truth. See the results of [Phase 1](docs/results/PHASE1_RESULTS.md),
[Phase 2](docs/results/PHASE2_RESULTS.md), [Phase 3](docs/results/PHASE3_RESULTS.md) and
[Phase 4](docs/results/PHASE4_RESULTS.md).

## Building

The code is C++20 with CMake. JUCE and sfizz are git submodules, so clone with
them:

```
git clone --recursive --shallow-submodules https://github.com/syflex/Live-band.git
```

### The drum and piano samples

The drum kit's percussion samples and the piano's (CC0, 81 MB) are downloaded, not
committed. Fetch them once with Python 3 before building; the build copies them next
to the app:

```
python tools/python/fetch_assets.py
```

### Windows (the target platform)

Use Visual Studio 2022 with the **Desktop development with C++** workload.
Open the folder in Visual Studio and pick the **Windows Release (MSVC)**
preset, or from a "Developer PowerShell for VS 2022". Use Release to play: the kit
is too slow in a Debug build.

```
cmake --preset windows-release
cmake --build --preset windows-release
ctest --preset windows-release
```

The app is written to `out/build/windows-release/LiveBand_artefacts/Release/`.
Every push also builds it on GitHub Actions; see
[docs/WINDOWS_SETUP.md](docs/WINDOWS_SETUP.md) for downloading that build.

### Linux (development only)

Linux builds are for compile checks and tests. The core library and its tests
need only a compiler:

```
cmake --preset linux-core && cmake --build --preset linux-core && ctest --preset linux-core
```

The full app also needs JUCE's Linux dependencies (see
`.github/workflows/ci.yml`), then uses the `linux-debug` or `linux-release`
preset.

### Offline evaluation

`lb-analyze` runs the app's voice analysis over audio files and writes CSVs.
The scripts in `tools/python` score it against reference pitch tracks and note
annotations:

```
python -m venv .venv && .venv/bin/pip install -r tools/python/requirements.txt
.venv/bin/python tools/python/fetch_vocadito.py
.venv/bin/python tools/python/eval_pitch.py  --analyzer <path to lb-analyze> --vocadito testdata/external/vocadito
.venv/bin/python tools/python/eval_onsets.py --analyzer <path to lb-analyze> --vocadito testdata/external/vocadito
```

`eval_key.py` scores the live key detection, on vocadito or on a synthetic test set of
sung melodies made by `make_key_testset.py` (see the
[Phase 3 results](docs/results/PHASE3_RESULTS.md)). CI runs these evaluations on every
push and fails if pitch or onset accuracy drops below the Phase 1 targets, or key
detection below its regression floors.

`lb-render` plays a style through the band's instruments offline into a WAV file, to
listen to a groove without an audio device:

```
lb-render --style assets/grooves/afrobeats --kit assets/sfz/afro-kit/afro-kit.sfz \
    --bass assets/sfz/bass/synth-bass.sfz --keys assets/sfz/keys/piano.sfz --pad assets/sfz/pad/warm-pad.sfz \
    --key G --plan Verse:8,Chorus:8 --out afrobeats.wav
```

`--style assets/grooves/worship-6-8` plays the worship style, and `--intense 4-8` plays
bars 4 to 7 (counted from 0) as if the singer were singing out.

The grooves and the instruments are generated by `tools/python/make_grooves.py`,
`tools/python/make_afro_kit.py` and `tools/python/make_band_kits.py`; edit those to
change them.

## Layout

```
src/common   lock-free queue, callback timing, allocation guard, pitch helpers ┐ core library:
src/audio    YIN pitch, onsets, vocal analyzer, decimator, FFT, latency       │ no JUCE, unit-tested
src/music    grooves, beat clock, player, tap tempo, key, click track         ┘
src/engine   audio engine, band controller, groove loader, session recorder, sfizz (JUCE)
src/ui       beat lights, note display and pitch view
src/Main.cpp, src/MainComponent.*   the app window
tests/       Catch2 tests; tests/engine drives the audio engine with a fake device
tools/       lb-analyze, lb-render, and Python scripts (evaluation, kit, grooves, fetching)
assets/      drum kit, bass, piano and pad (samples downloaded by tools/python/fetch_assets.py), grooves
libs/        JUCE and sfizz submodules
```
